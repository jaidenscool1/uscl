# NHL 15 (BLUS31436)

Disc 1.00 (SFO version 1.01), update **1.01** installed (EA). BlazeSDK **3.19.09.0-eac.01-nhl.01** (Blaze 3.x "heat2"), same generation as Madden NFL 25
(`games/BLUS31178.md`). Runs on `uscl-blaze`. NHL 15 emulates cleanly in RPCS3, so it has become the **lead EA
Sports test vehicle** (Madden hits an unrelated FGGameSim PPU crash ~52s in).

## Status (2026-11-09) — LOGS IN AND CONNECTS TO THE EA SERVERS (online menus reached 2026-11-13, below)

NHL 15 now completes the entire Blaze 3.x login and reaches **"Retrieving data from server"** with the online
music ticker playing — up from an instant "The EA servers are not available". Full flow working:
`getServerInstance` (TLS) → `preAuth` → `fetchClientConfig` × N → `ps3Login` → the post-login notifications →
`postAuth` → `updateNetworkInfo` → the full online bootstrap (Messaging, AssociationLists, Clubs, Stats, config).

### How login was solved (see `uscl-blaze/README.md` + the server's `docs/EA-Sports-Blaze3-heat2.md`)
1. **TLS.** NHL's ProtoSSL only speaks SSLv3+RC4, which OpenSSL 3.x removed. Fixed with
   `uscl-blaze/tls/tlsproxy_legacy.py` (tlslite-ng, keeps SSLv3/RC4) on 42127.
2. **Ticket.** `HostTicketKey` in `settings.json` = our RPCN's uncompressed public point, so self-signed tickets
   validate; expiry hard-reject relaxed.
3. **`ps3Login` response = the real `ConsoleLoginResponse`**, persona under **`DSNM`** (the earlier DS2-derived
   `PNAM/DPTS` tags were unreadable — the SDK read no persona and logged straight back out).
4. **`UserAuthenticated` (UserSessions notification 8)** — the local-user login-completion signal the SDK blocks
   on. Without it NHL pinged a few times then sent `logout` (70). Sent after login as **8 → 2 → 5**.

Shapes 3/4 were RE'd from `ceinydO/fifa17-ps3-online`. The shared **Stats** component (`getKeyScopesMap`) was
also added.

## Ticker crash solved: OSDKSettings (2026-11-12, uscl-blaze patch 0015)

The old blocker (main PPU thread null-deref at **`0x008b1aec`**, ~89 s, "retrieving data") is fixed. Component
**2249 is `Blaze::OSDKSettings`** (`fetchSettings` = 1, `fetchSettingsGroups` = 2), not "OsdkTicker2". The game
builds its settings groups from `fetchSettingsGroups` and looks `O_SG_TCKR` up with no null check; our empty reply
never created it. The server now sends the five groups (`O_SG_NRAD/QMSG/SYSS/TCKR/USER`, TDF tags read from the
EBOOT), the ticker settings `O_TKfriend/O_TKsport/O_TKfilter`, and `O_SG_USER`'s views. NHL now runs on to Stats
15, Util 12, Stats 3 and Authentication 30.

Tried first: an error for 2249: no crash, but the game logs out ("The EA servers are not available") right after.

## Online menus reached (2026-11-13)

- **User settings:** the game creates its matchmaking settings itself (`O_JS`, `O_GM`, `O_MIN`, …); the server only
  defines the account opt-ins `O_SPAMEA` and `O_SPAMPART` (uscl-blaze patch 0015). Serving more corrupts the game's
  settings manager (crash `0x828b88`).
- **Dynamic messages:** the online main menu crashed at `0x7f9528`: the OSDK message rotation reads message 0
  without checking its list has one. Messages served by us never reached that list, so the fix is client-side:
  RPCS3 built-in USCL patch "dynamic messages with none to show" (uscl-rpcs3 patch 0012; applies online too).

Tested (RPCS3 0.0.43 USCL build, `USCL_ONLINE=1`, one PC): EA account screen → terms → **main menu** →
PLAY → **ONLINE** ("GM CONNECTED", Online Versus Play, EASHL, Arena, Team Play, Shootout) → **Online Versus
Play** hub (live player counters). Stable for minutes.

## Update 1.01, the roster check and the first matchmaking request (2026-11-13)

USCL goes online only on a game's newest update, so everything now runs on **1.01** (Sony's only patch; PPU hash
`PPU-51362497…`). 1.01 moves the code in this area by a constant **+0x240** (`tools/dev-scripts/portaddr.py` maps
addresses between builds); older addresses in this file are for 1.00.

- **Dynamic messages patch ported** (`0x7f9528` → `0x7f9768`), uscl-rpcs3 patch 0013. Tested: account screen →
  terms → main menu → PLAY → ONLINE → Online Versus Play, as on 1.00.
- **Roster check solved (client side).** The config reader (`0x89245c`) reads `URL`, `CRC` and the optional checksum
  from the `OSDK_ROSTER` config and hands them to the checker (`0xf488f8`). That compares `CRC` with a string the
  game builds itself: base-62 hashes of its roster database tables (`0x3e02f0`), and only when the game's
  "roster download enabled" flag (byte `0x2379ed1`) is set. EA's roster files are gone and the hash can't be known
  server-side, but every USCL player runs the same update and disc roster, so the built-in patch "the game's own
  rosters are current" (`0xf489b8`: read the flag as off; uscl-rpcs3 0013) makes the check pass. Serving
  `CRC=0` or an empty config does not.
- **Result:** Search now sends **`startMatchmaking`** (GameManager 13), the first time NHL gets that far.

## Remaining blocker: Blaze 3.x game setup

The server's matchmaking was written for NBA Jam (Blaze 2.x). For 3.x clients it now decodes the request (heat2
types 7 to 11) and sends notification 20 as 3.x's `NotifyGameSetup` (game, roster, queue, setup reason with the
matchmaking result) instead of 2.x's `NotifyJoinGame` + `NotifyMatchmakingFinished` (uscl-blaze patch 0017, WIP).
NHL takes that and then null-derefs on the main thread at **`0xa2ee44`**: a telemetry function (keys `gsid`,
`gsrv`, `gsv2`, `peer`) calls `game->vtable[0x5c]()` and reads the result's `+0x3c` (compared with 3 = the
`IpAddress` member of a `NetworkAddress`), so the game's host/server network address comes back null. Naming the
platform host as topology host did not change it. Next: decode the notification we send (tap capture) and check
`HNET`, then find the Game class's vtable to see what slot `0x5c` returns. After that: a second copy
(`rpcs3-ea-probe2`, uscltest2, has 1.01) to match two players.
