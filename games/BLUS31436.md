# NHL 15 (BLUS31436)

Disc 1.01 (EA). BlazeSDK **3.19.09.0-eac.01-nhl.01** (Blaze 3.x "heat2"), same generation as Madden NFL 25
(`games/BLUS31178.md`). Runs on `uscl-blaze`. NHL 15 emulates cleanly in RPCS3, so it has become the **lead EA
Sports test vehicle** (Madden hits an unrelated FGGameSim PPU crash ~52s in).

## Status (2026-11-09) — LOGS IN AND CONNECTS TO THE EA SERVERS

NHL 15 now completes the entire Blaze 3.x login and reaches **"Retrieving data from server"** with the online
music ticker playing — up from an instant "The EA servers are not available". Full flow working:
`getServerInstance` (TLS) → `preAuth` → `fetchClientConfig` × N → `ps3Login` → the post-login notifications →
`postAuth` → `updateNetworkInfo` → the full online bootstrap (Messaging, AssociationLists, Clubs, Stats, config).

### How login was solved (see `uscl-blaze/README.md` + the server's `docs/EA-Sports-Blaze3-heat2.md`)
1. **TLS.** NHL's ProtoSSL only speaks SSLv3+RC4, which OpenSSL 3.x removed. Fixed with
   `uscl-blaze/tls/tlsproxy_legacy.py` (tlslite-ng, keeps SSLv3/RC4) on 42127.
2. **Ticket.** `HostTicketKey` in `settings.json` = our RPCN's uncompressed public point, so self-signed tickets
   validate; expiry hard-reject relaxed.
3. **`ps3Login` response = the real `ConsoleLoginResponse`**, persona under **`DSNM`** (the earlier DS2-derived
   `PNAM/DPTS` tags were unreadable — the SDK read no persona and logged straight back out).
4. **`UserAuthenticated` (UserSessions notification 8)** — the local-user login-completion signal the SDK blocks
   on. Without it NHL pinged a few times then sent `logout` (70). Sent after login as **8 → 2 → 5**.

Shapes 3/4 were RE'd from `ceinydO/fifa17-ps3-online`. The shared **Stats** component (`getKeyScopesMap`) was
also added.

## Remaining blocker — one diagnosed, server-fixable crash

After the full online bootstrap, NHL's main PPU thread null-derefs at **PC `0x008b1aec`** (deterministic, ~89s)
while "retrieving data". The Blaze session stays healthy (keeps ping/ponging) — it's the **game** crashing.

Root cause (from EBOOT disassembly): the "update ticker subsystem" function does
`stgm_manager->lookup("O_SG_TCKR")` → **null** → derefs it. The `"stgm"` settings manager is initialized
(97 refs); only the **ticker settings group `O_SG_TCKR`** is missing.

**Proven server-fixable, not an emulator bug:** the PPU **interpreter** crashes identically. Ruled out: Stats
response content; `OSDK_TICKER` fetchClientConfig content (served real fields, group still not created). The game
calls the `OsdkTicker2` component (2249/1 + 2249/2) right before the crash and we return empty success.

**Next step:** (a) cheapest — return an error (`OSDKTICKER2_ERR_NOT_REGISTERED`) for 2249 so the game disables
the ticker and continues to the menu; or (b) RE the `OsdkTicker2` `RegisterResponse` so the group is created.
Disassembly toolchain + full trace in the server's `docs/EA-Sports-Blaze3-heat2.md`.
