# Call of Duty: Black Ops II (PS4, CUSA57548)

Runs on the USCL shadPS4 fork (`uscl-shadps4`) with shadNet (`uscl-shadnet`) and uscl-dw (title 2430, auth3 on
TCP 443). Two-PC public matches over the bridge (`bo2ps4` preset) work. PS3 version: `BLUS31011.md`.

## Crossplay with PS3 (work in progress)
Three layers between the games, each must be translated by the bridge:
1. **Peer DTLS** (Demonware bdDTLS, below): both builds encrypt game UDP. The bridge has to end it on each side.
2. **Lobby / party messages and the connect string** (`protocol` 2093 on PS3, 2097 on PS4, `netfieldchk`).
3. **In-game messages**: snapshots and entity fields (same fields, different order and encoder ids, see
   `netfields_*.txt` in the RE folder), Huffman table and asset ids not compared yet.

### Peer DTLS (from PS4 codmp.elf; addresses are Ghidra's, game = +0x400000)
Every field is written by bdBytePacker, a raw memcpy, so it is in **native byte order**: little-endian on PS4,
big-endian on PS3.

- Header (6 bytes, `0x8a21a0`): u8 type, u8 version = 2, u16 vtag, u16 extra (sequence number in data).
- INIT, type 1 (`0x8a2c40`, serializer `0x8a1fa0`): header (vtag 0) + u16 init tag + 8-byte secID. Sent up to 6x.
- INIT_ACK, type 2 (`0x8a4b90`, `0x8a5ad0`): header (vtag = the peer's init tag) + u32 time + u32 cookie MAC +
  5x u16 (tags) + bdAddr blob (<= 0x88 bytes) + 8-byte secID. The cookie MAC is 4 bytes of HMAC-SHA1 keyed with a
  16-byte per-process secret; only the side that made it checks it (`0x8a4e10`).
- COOKIE_ECHO, type 3 (`0x8a4970`, `0x8a2660`): header + copy of the INIT_ACK body + 0x25 bytes (not decoded
  yet) + secID + 100-byte ECC public key of the initiator (libtomcrypt `ecc_export`, zero padded).
- COOKIE_ACK (`0x8a52d0`): the responder's 100-byte ECC public key. Handled in `0x8a40f0`.
- Session key (`calculateSharedKey`, `0x8a5090`): secKey = bdSecurityKeyMap[secID] (16 bytes);
  key = Tiger-192(ECDH secret (28 bytes, a 224-bit curve) || secKey), 24 bytes, used as the 3DES key.
- DATA (`0x8a5f70` / `0x8a64b0`): header (16-bit sequence) + 8-byte MAC + 3DES-CBC of [u16 length + payload]
  padded to 8. IV = first 8 bytes of Tiger-192(32-bit sequence, native order), the 16-bit number widened by
  bdSequenceNumber (`0x8ce640`). MAC = HMAC-SHA1(key) over header + ciphertext, first 8 bytes.
- PS3 (`t6mp.elf`) uses the same library: `calculateSharedKey` at `0x7fa3e4`, bdECCKey at `0x86bd74`/`0x86be28`.
  Only the byte order differs.
- **Parked (2026-10-28):** translating between PS3 and PS4 would mean the bridge stepping into this encrypted
  handshake; not pursued.

- Packet types (dispatcher `0x8a3090`): 1 INIT, 2 INIT_ACK, 3 COOKIE_ECHO, 4 COOKIE_ACK, 5 ERROR, 6 DATA.
- ECC (`0x8ce8c0`): libtomcrypt `ecc_make_key(yarrow, 28)` = NIST P-224, a new key per association; public key
  is `ecc_export` (DER: flags, key size, x, y), the secret is the 28-byte x coordinate.
