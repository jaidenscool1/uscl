# Madden NFL 25 (BLUS31178)

Disc 1.00. Profiled 2026-11-06 on the uscl-rpcs3 rebase (upstream eee3f0f): boots to the title screen, picture
correct; first boot compiles for ~4 min.

## How it plays online
EA **Blaze**, BlazeSDK `13.3.0.3.1` (the Madden 14/25 code base), through RPCN for the PSN side:
| What | Where |
|---|---|
| login proof | `sceNpManagerRequestTicket2`, service `UP0006-BLUS31178_00`, requested right at boot |
| redirector | `gosredirector.ea.com` TCP **42127, TLS** (SSL 3.0 record, TLS 1.1 ClientHello, EA's ProtoSSL) |
| crash reports | `reports.tools.gos.ea.com` TCP 443 TLS (bug sentry, can stay unanswered) |
| also in the EBOOT | `gosca.ea.com:44125/redirector` (HTTPS), `gosredirector.online.ea.com`, `peach.online.ea.com`, QoS `/qos/*`, Facebook sharing |

The game connects to the redirector after START on the title screen; unanswered, it shows "The EA servers are not
available at this time. Please try again later."

## Status (2026-11-07): ProtoSSL TLS solved; needs a Blaze 3.x codec
Through USCL's Blaze stand-in (`uscl-blaze`) with the TLS front (`uscl-blaze/tls`):
1. **ProtoSSL bypass works.** Madden's ProtoSSL **accepts the forged `gosredirector.ea.com` cert** (MD5-RSA, from
   blaze-ssl-async, MIT) over **SSLv3 / AES256-SHA**. No PPU patch needed. The `tlsproxy.py` front terminates TLS on
   42127 and forwards to the Blaze server on 42100.
2. **Redirector works.** Madden sends its `getServerInstance` over the TLS (BlazeSDK `13.3.0.3.1`, service
   `MADDEN2014_PS3`, its RPCN ticket). Patch 0004 answers it with `SECU=1` + the TLS port (Blaze 3.x runs the whole
   session over TLS, unlike NBA Jam's plaintext Blaze).
3. **Redirector solved in heat2; session runs plaintext; Madden now reaches the EA handshake.** Two fixes
   (`uscl-blaze` patch 0005, server `Heat2Writer.cs` + `GetServerInstanceHandler.cs`):
   - **heat2 getServerInstance response.** The 2.x model encoder produced heat1 (first type byte `0xd0`) that Madden
     couldn't parse, so it fell back to `127.0.0.1:443` and failed. The response is now hand-built in **heat2**
     (`3-byte tag + full type byte`; **little-endian** varint ints — different from heat1's big-endian `EncodeVlq`):
     `ADDR` union case 0 → `VALU{ IP, PORT }` ; `SECU` ; `XDNS`. Madden reads it and connects to the session port.
   - **Plaintext session (SECU=0).** A SECU=1 address given as a bare IP makes the client's ProtoSSL **refuse to start
     TLS** (no hostname/CN to validate) — it opens the socket and immediately closes → "EA servers not available".
     Returning **SECU=0** makes Madden connect the session **plaintext** straight to the Blaze port (42100); only the
     redirector hop stays TLS. No session TLS proxy or hostname-cert needed.
   - **Result (verified 2026-11-07):** Madden connects 42127 (redirector, TLS) → 42100 (session, plaintext), sends
     **`preAuth`** (Util `0x09/0x07`) + `fetchClientConfig` for `OSDK_CORE/CLIENT/NUCLEUS/...`, and the UI shows
     **"uscltest is connecting to the EA Servers"** (no longer the error). The real session capture is
     `uscl-blaze/tls/madden-session-plaintext.hex`.
   - **Remaining:** a heat2 **codec for the session** — the server still answers these in heat1, so Madden stalls
     mid-handshake (RPCS3: "PS3 application has likely crashed"). The session commands are the **same shape as NBA
     Jam's** (preAuth, fetchClientConfig OSDK_*, auth, then matchmaking), so the existing handlers just need heat2
     decode/encode. NHL 15 rides the same codec.

Reference (read, don't copy — no license): Zamboni (NHL 10 → Legacy, 2026) implements Blaze 3.x on PS3; its
`ppu-patches` repo and BlazeSDK fork show the 3.x structures. NHL 15 (owner's library, serial not checked) is the
same EA Sports Blaze 3.x generation and would come along with the codec.
