# NBA Jam (BLUS30696)

Disc 1.00 (EBOOT built Sep 27 2010). Profiled 2026-11-06 on the uscl-rpcs3 rebase (upstream eee3f0f): boots to the
title and menus, picture correct, first boot compiles for ~5 min, then about 12 s to the main thread.

## How it plays online
EA **Blaze**, BlazeSDK `2.11.4.1` (same era as Skate 3's), through RPCN for the PSN side:
| What | Where |
|---|---|
| login proof | `sceNpManagerRequestTicket2`, service `UP0006-BLUS30696_00`: an RPCN ticket. Needs PSN status **RPCN** (Simulated stops the game: "RPCN is required to use PSN online features") |
| redirector | `gosredirector.ea.com` TCP **42100, plain (no TLS)** |
| Blaze server | whatever the redirector returns (`standardSecure` profile, so normally SSL) |
| QoS / NAT checks | HTTP `/qos/qos`, `/qos/firewall`, `/qos/firetype`, `getPeerAddress`, on the addresses Blaze hands out |
| UPnP | DirtySock probes the router (`192.168.1.1:5000`) at startup, harmless |

The redirector request, captured at Main menu → Play Online (421 bytes, Blaze header `0199 0005 0001 ...`:
component 5 Redirector, command 1 getServerInstance) carries `2.11.4.1`, `JAM` / `JAM_PS3`, env `prod`,
service name **`nbajam-2010-ps3`**, connection profile `standardSecure`, and the RPCN ticket for the signed-in
user. With nothing answering, the game says "The EA servers are not available at this time".

Hosts the EBOOT names (all go in the IP swap list): `gosredirector.ea.com`, `gosredirector.online.ea.com`,
`gosredirector.scert.ea.com`, `gosredirector.stest.ea.com`, `peach.online.ea.com`, `demangler.ea.com`.

## Status: online works (2026-11-07)
NBA Jam plays through USCL's Blaze stand-in (`uscl-blaze/`, built on Skate3BlazeServer). Verified with two
instances on one PC (RPCN accounts uscltest / uscltest2):
1. Both sign in: the server accepts their RPCN tickets (host RPCN signs with `ticket_private.pem`, server trusts
   its `HostTicketKey`). Full EA-account sign-in flow (Welcome Back / Information Sharing) passes.
2. Both start a **ranked 1v1 search** and matchmake into the **same game**: the server makes the game (host =
   first searcher, the other joins), relay on 17000+gameId.
3. Both reach the **head-to-head CHOOSE TEAMS lobby seeing each other as human opponents**, and the relay forwards
   game traffic **both ways** between them (logged `pkt 3->4` / `pkt 4->3` on the relay port).

What made it work (in `uscl-blaze/patches`, on top of the Skate 3 server):
- trust the host RPCN's ticket key; `fetchClientConfig` (OSDK_* sections); tolerant TDF fields; empty success for
  commands the server doesn't implement (NBA Jam aborts its login on `ERR_COMMAND_NOT_FOUND`);
- BlazeSDK 2.x matchmaking (no `ATTR` map): the server creates a **relay-backed** game (dirtycast failover), so two
  players — including two instances on one PC — connect through the relay instead of failing direct peer-to-peer.

Not yet shown: the match tip-off rendered. The two automated pads couldn't both complete team-select because a
leftover virtual pad on this PC (from an earlier session, can't be removed here) scrambles SDL controller
enumeration — a test-harness issue, not the game or server. A clean two-PC test (or clean pads) finishes it.

Probe setup on jaiden-pc: `~/.local/share/uscl/rpcs3-ea-probe` (uscltest) and `-ea-probe2` (uscltest2), both with
`PSN status: RPCN`, RPCN host `127.0.0.3:31513` (a probe RPCN with ticket signing, data in `~/.local/share/uscl/
rpcn-probe`), and the IP swap list pointing every EA name at 127.0.0.1. Server source + build: `~/src/nbajam-blaze`
(branch `uscl-nbajam`), runs from `~/.local/share/uscl/nbajam-server`. Drive scripts in the job tmp
(`nba-copy.sh a|b`).
