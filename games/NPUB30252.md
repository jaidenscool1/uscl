# Gotham City Impostors (NPUB30252)

PSN-only digital game (Monolith / WB, 2012). Installed as the trial package plus the full-game unlock bought on
PSN: the licence `UP1018-NPUB30252_00-UNLOCKFULLGAME00.rap` and the unlock `.edat` go in
`dev_hdd0/home/00000001/exdata/` (the player's own, never committed). The online servers were shut down with
GameSpy in 2014.

## Profiled 2026-10-26 (USCL's RPCS3, Linux)
- **Licence: full game.** RPCS3 logs `Found EDAT file …UNLOCKFULLGAME00.edat for trial game`, and the game's own
  check `sceNpDrmVerifyUpgradeLicense2("UP1018-NPUB30252_00-UNLOCKFULLGAME00")` succeeds (no error), so the game
  sees the upgrade as bought. The menus themselves couldn't be reached yet (below), so trial limits aren't
  checked on screen.
- **It can't get past the title screen without GameSpy.** Pressing ✕ goes to "Loading Profile": the player
  profile lives on GameSpy. What happens depends on what answers:
  - RPCN not reachable: no PSN ticket, "Loading Profile" forever (the game polls `sceNpManagerGetTicket`).
  - RPCN signed in: ticket OK, then "Authentication Error: No GameSpy connection detected" → back to the title.
    Same loop every time; there is no offline way into the menu. This is most likely what a real PS3 shows today.
  - Our probe answering the availability check (`tools/dev-scripts/gs.py`): the game moves on to
    `sirenps3.api.gamespy.net` TCP 443 and waits there, "Loading Profile" again.
- PSN imports: NP tickets (`sceNpManagerRequestTicket2` once signed in), Signaling, Basic, Lookup, Commerce2, Drm,
  Trophy; cellHttp/Https/Ssl. No Demonware, no Blaze.

### Online flow seen so far
| Step | Host | What |
|---|---|---|
| 1 | `sirenps3.available.gamespy.com` UDP 27900 | `09 00000000 "sirenps3\0"` → answer `fe fd 09 00000000` (available). Done by the probe |
| 2 | `sirenps3.api.gamespy.net` TCP 443 | SSL **3.0** ClientHello offering only `RC4-MD5` (0x0004): GameSpy SDK's own SSL. Next: the PS3 login with the NP ticket (GameSpy AuthService, SOAP) |

Test setup (local, nothing committed besides these notes): USCL's RPCS3 with a per-game config
`custom_configs/config_NPUB30252.yml` holding an `IP swap list` that points `sirenps3.available.gamespy.com`
and `sirenps3.api.gamespy.net` at 127.0.0.1; uscl-rpcn with `USCL_LOCAL=1` plus a UDP forward 3657 → 3757
(what the bridge does) so RPCN signaling answers; a pad config (USCL's RPCS3 ships without one).

## Reviving it
GameSpy is a known route: [OpenSpy](https://openspy.net) runs replacement GameSpy servers and already brings back
many PC/console games. What GameSpy games use, in order:
1. `<game>.available.gamespy.com` UDP 27900: "is this game online?" check. Easy to answer ourselves.
2. `<game>.master.gamespy.com` / `<game>.ms?.gamespy.com`: server/lobby lists (needs the game's secret key, found
   in the executable).
3. `gpcm` / `gpsp.gamespy.com`: sign-in and presence (on PS3 probably via the NP ticket).
4. `natneg?.gamespy.com`: NAT punch-through, then peer-to-peer or a player-hosted server.
5. `sirenps3.sake.gamespy.com` / `gamestats`: stats and unlocks over HTTP(S).

What the login (online flow step 2) needs: an SSLv3 / RC4-MD5 server (modern OpenSSL dropped SSLv3: a small hand-written one or an old
OpenSSL build), then the AuthService login reply. That reply carries a certificate signed by GameSpy's private key,
which the game checks against a public key built into the executable; community revivals replace that key with
their own via a game patch (an RPCS3 `patch.yml` entry here). Check whether OpenSpy already has this for PS3
GameSpy titles before writing it.

Effort guess: medium. Smaller than Demonware/Blaze if OpenSpy (or its open-source server code) covers `sirenps3`.
Next steps:
1. The SSLv3 login (online flow step 2) on `sirenps3.api.gamespy.net`, then log the next names it asks for.
2. Ask the OpenSpy community whether `sirenps3` is supported; if not, pull the game key from the decrypted EBOOT
   (`unself.py` with the licence's klic) and run their server code locally.
3. HTTPS hosts (sake) need the game to accept our certificate: check how it validates (`cellSsl` CA list).
