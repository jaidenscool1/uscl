# Call of Duty: Modern Warfare 2 (BLUS30377)

Disc "USA, Korea" + update 1.14 (`UP0002-BLUS30377_00-MW2P000000000014-A0114-V0100-PE.pkg`, from Sony's update
server). Demonware title id 5280, klicensee `InfinityWardKey\0`. Multiplayer is `default_mp.self` (the main menu's
MULTIPLAYER reboots into it).

## How it plays online
| What | Where |
|---|---|
| login (`Ps3ForMmpRequest`, like BO2) | `mw2-ps3-auth.mmp3.demonware.net` TCP 3074 → uscl-dw |
| lobby: playlists, MOTD, stats, matchmaking | `mw2-ps3-lsg.live.mmp3.demonware.net` TCP 3074 → uscl-dw |
| NAT type | `mw2-stun.us/eu.demonware.net` UDP 3074 → uscl-dw (reports Open) |
| IWNet (`*.ps3.iw4.iwnet.infinityward.com`) | swapped to 127.0.0.1, nothing answers; the game doesn't need it |
| game traffic | peer to peer, UDP 3074 |

So it uses the same ports as BO2 (`uscl-bridge host bo2`) and the USCL panel treats it like BO2.

## What's different from BO2 (uscl-dw patch 0013, `lobby/mw2.rs`)
MW2 has an older Demonware. Layouts are from [elliot1377/mw2-ps3-server](https://github.com/elliot1377/mw2-ps3-server)
(MIT, its `docs/PROTOCOL.md`), checked against our 1.14 executable:
- The lobby connection opens with one batched frame: `ff ff 00 00`, then `[u32 length][message]`... (its length
  comes out one byte short).
- Tasks and replies are **bit buffers**: one type-checked bit, then 5-bit type tags, values LSB first; strings and
  blobs unaligned. Only the bandwidth test (service 18) is plain bytes.
- The client matches replies to tasks first in, first out: every task gets an answer, unknown ones an empty OK.
- Storage (10): task 8 lists the publisher files (result type 7), task 5 `[u8 0][u64 id]` downloads one (result
  type 1); the game asks for `playlists.patch3` and `motd-english.txt` by id. Task 7 (its own files) gets an
  empty list.
- Matchmaking (5): 1 create `[u8][blob addr][blob id][blob key][int32 x 13]` → `[u32 1][blob session id][blob
  key]`, 2 update, 3 delete `[u8][blob id]`, 5 find `[u8][int32 x 9]` → `[u32 n]` + per game the host's create
  fields. Matchmaking replies echo the task id where storage puts a result type, and carry one count
  ([Tustin/mw2-rpcs3](https://github.com/Tustin/mw2-rpcs3)'s notes on the game's parser). The 13 create ints are
  4 slot counts (open public, filled public, open private, filled private), then playlist at 5, playlist
  version at 6, netcode (139) at 8; a search has playlist at 3, netcode at 4, version at 6, and only gets
  games where all three match.
- Bandwidth test (18): plain bytes, answered with lobby message type 5. Phase 1 → `[u64 transaction][u8 0][u32
  packet size, count, sender wait, send ms, receiver wait, receive ms, linger][u16 port][IPv4][8-byte token]`; the
  game then sends 5 x 512 bytes to that UDP port (our NAT discovery socket, which ignores them). Finalize (5 x u32
  of its own) → `[u64][u8 0][u32 bytes, ms, average / first / last sequence]`. **This decides whether anyone can
  join**: from it the host computes its upload; under 256000 bit/s (or zeros, which give NaN) it opens its lobby
  with 0 public / 8 private slots and turns every joiner away. We answer as for 2560 bytes in 50 ms (Tustin found
  a 50 ms send is what lets players join). Visible in Private Match: "Recommended Max Players" goes from 2 to 12.

## Publisher files (`uscl-dw/mw2-files`, served from `storage/publisher/5280/`)
`playlists.patch3` is the playlist text (`version`, `gametype`, `playlist N` blocks, entries
`map,gametype,weight`); the parser is at 0x242038 in 1.14 MP, the download at 0x2f61e8 (up to 128 KiB). Without
it MP stops at "Fetching Playlists". From elliot1377/mw2-ps3-server (see `NOTICE`).

## Status (2026-10-25, two copies on one PC)
Sign in, NAT Open, playlists, the online menu and Find Game work. Two copies matchmade: B's search found A's
Team Deathmatch lobby and joined it (2 players, waiting for 8), and in Hardcore Free-for-all (2 players
minimum) both loaded Estate and played the same match. Peer traffic goes straight between the games (UDP 3076
here, NAT traversal type 0x0d → 0x0c, then QoS and the party join); nothing of it passes our server.

Not working: **invites** (the game opens the PS3's friend list, `sceNpFriendlist`, which RPCS3 doesn't
implement), so friends play together by picking the same playlist. Next: two PCs over the Steam tunnel.

## Testing tips
- Two copies on one PC: RPCS3 bind addresses 127.0.0.1 / 127.0.0.2, and run uscl-rpcn **without** `USCL_LOCAL`
  on TCP 31313 (no bridge): with the bridge, RPCN signaling answers only reach 127.0.0.1, the second copy logs
  "Failed to get a reply from RPCN signaling" and MW2 says you aren't signed in to PSN.
- The stock playlists start TDM at 8 players; Hardcore Free-for-all (playlist 4) starts at 2.
- Menus ignore A until the d-pad has moved the focus once (the virtual pad: `dpad`, then `press A`).
- The first boot of each executable compiles PPU modules for a few minutes.
