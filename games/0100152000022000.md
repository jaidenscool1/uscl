# Mario Kart 8 Deluxe (Switch)

Title ID: `0100152000022000`. Base-game container found locally; filename indicates v0. Title/version metadata has not been verified by decrypting the container. The local update and Booster Course archives are separate content, installed through Eden rather than imported as launchable games.

USCL route: Eden local wireless (LDN), with an Eden room on host loopback UDP 24872 transported to session members by `uscl-bridge host switch`. Start or join the Steam session before launching the game, then choose Wireless Play in the game. Every player needs matching emulator, game-update and DLC versions.

Implemented: library scan, Switch core selection, isolated profile, console-file import UI, automatic CLI room join, room-server lifecycle, and Steam UDP forwarding preset. The default route does not start PS3 services.

Validated 2026-11-09: container discovery, shell build/self-test, CLI room-join syntax against Eden v0.2.1, and bridge unit tests.

## Local boot tests, 2026-11-09–10

The player's provided keys were imported privately into the isolated preview profile. No Switch firmware was available. The installed application and real player profiles were not changed.

- The desktop forced `SDL_VIDEODRIVER=wayland`; Eden v0.2.1's bundled SDL2 failed to initialize it. Explicit X11/XWayland allowed the core to start. USCL now supplies this fallback when a Wayland-only setting is inherited and DISPLAY is available.
- Base game: launched from the actual USCL library entry, rendered the title at approximately 60 FPS, accepted L+R, then stalled on loading. The log included an NVMap page-mapping assertion and `Cannot execute instruction at unmapped address 0x000000`.
- Installed the locally supplied update container, version integer `1507328`. Eden confirms both ExeFS and RomFS update application (`v0.23.0` internally); the graphical frontend identifies the game as **4.0.1 (64-bit)**.
- Updated game in the SDL frontend: no playable rendered menu was reached. Both default and synchronous GPU modes were attempted without a successful race.
- Updated game in the graphical frontend, using native Qt keyboard bindings: title screen rendered at approximately 60 FPS and accepted L+R. It then stalled at **Select a Mii**. The log reported an empty saved Mii database, six default Miis returned by the service, and an ARM64 invalid instruction address at zero. Firmware absence is a test limitation, not a proven cause of that exception.

The blanket firmware prerequisite in USCL was removed: some games can at least boot without it, and the core should report a game's actual requirements. The import option remains available.

**Result: title-screen boot verified; a playable race, physical controllers, and multiplayer are not verified.** Do not mark this game supported for play yet. Next: reproduce with the player's firmware and investigate core compatibility before a two-PC Wireless Play race. The shared Qt/SDL keyboard configuration also needs validation: the diagnostic GUI test required Qt key codes rather than SDL scancodes.
